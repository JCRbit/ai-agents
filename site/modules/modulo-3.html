03 · Herramientas: cómo decide el modelo

Tool schemas, function calling, y por qué la descripción de una herramienta pesa más que su implementación.

Teoría

Qué es un tool schema

Una herramienta se define con un nombre, una descripción en lenguaje natural — la parte que más influye en si el modelo la elige bien — y sus parámetros de entrada, normalmente como JSON Schema.

La mecánica real del function calling

El modelo no ejecuta la herramienta. Devuelve una estructura pidiendo llamarla con ciertos argumentos; el código de la aplicación la ejecuta de verdad y le devuelve el resultado como una nueva Observation. El modelo nunca toca el mundo exterior directamente.

Cómo "decide" el modelo qué herramienta usar

No hay un enrutador explícito. Dado el conjunto de herramientas disponibles y el historial, el modelo genera la salida más probable. Una descripción ambigua produce elecciones erróneas aunque la función esté bien programada; con muchas herramientas parecidas, la tasa de acierto baja.

Cuando una herramienta falla

El error se devuelve al modelo como una Observation de error. El modelo puede razonar sobre ello y decidir reintentar, usar una alternativa, o informar de que no pudo completar la tarea.
