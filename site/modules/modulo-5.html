05 · Panorama de la industria

Dónde encajan los frameworks reales, y qué lecciones históricas existen sobre autonomía sin control.

Teoría

Frameworks reales

LangChain / LangGraph como orquestadores populares para construir bucles de agentes; el Claude Agent SDK como ejemplo de SDK oficial pensado específicamente para este patrón. La propia Anthropic formalizó la distinción entre workflow y agente que abrió el Módulo 1 en un artículo de ingeniería de referencia — primer enlace de la lista de abajo.

AutoGPT como caso histórico

Uno de los primeros intentos populares (2023) de "agente totalmente autónomo", sin un criterio de parada robusto ni supervisión — un buen ejemplo real de por qué el Módulo 4 importa tanto en la práctica.

Multi-agente

Cuándo tiene sentido dividir el trabajo entre varios agentes especializados que se coordinan (uno planifica, otro ejecuta, otro revisa) en lugar de un único agente generalista.

Para seguir explorando

Este módulo de cierre no incluye demo ni laboratorio — son las referencias para quien quiera seguir después del tutorial.

  • Building Effective Agents anthropic.com · artículo de ingeniería

    El propio artículo de Anthropic que formaliza la distinción entre workflow (pasos fijados de antemano) y agente (el modelo decide el siguiente paso) — la idea que abre el Módulo 1 de este tutorial.

  • LangGraph — Overview docs.langchain.com · documentación oficial

    Framework de orquestación que modela un agente como un grafo con estado: nodos, transiciones condicionales y puntos de persistencia para pausar y reanudar.

  • Claude Agent SDK — Overview platform.claude.com · documentación oficial

    El SDK con el que Anthropic construye Claude Code: mismo bucle de agente, herramientas y gestión de contexto, expuesto como librería para Python y TypeScript.

  • AutoGPT en.wikipedia.org · resumen histórico

    Contexto del caso citado en el Módulo 4: por qué un agente sin criterio de parada robusto cae en bucles infinitos, y cómo evolucionó el proyecto después de 2023.

Caso práctico transversal · Paso 5 de 5

Una incidencia: investigar una aplicación caída

Seguimos el mismo caso a lo largo del tutorial. El agente debe investigar una incidencia, utilizar herramientas con cuidado y verificar el resultado antes de detenerse.

ETAPA 05 / 05

Extraer la lección

El servicio responde correctamente después de la corrección y una comprobación final confirma el resultado.

Qué aprender: El agente se detiene porque se cumple un criterio observable, no simplemente porque el modelo haya dicho «terminado».
